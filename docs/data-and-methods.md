# 데이터와 계산 방법

이 문서는 광교호수공원 그늘 지도가 어떤 자료를 사용하고, 그 자료를 어떤 규칙으로 그림자와 그늘 비율로 바꾸는지 설명합니다. 화면 사용법은 루트 [README](../README.md)를 참고하세요.

## 분석 범위

- 분석 대상은 광교호수공원의 공원 육지와 공원 안 보행로입니다.
- 호수 수면과 건물 footprint는 공원 육지에서 제외합니다.
- 그림자를 만들 수 있는 건물·수목·시설은 공원과 주변 500 m 범위(AOI)에서 수집합니다.
- 공원 경계와 저수지는 [scripts/fetch-osm.ts](../scripts/fetch-osm.ts)가 OSM 자료에서 만듭니다.
- 보행로는 AOI에서 받은 뒤 [scripts/select-park-paths.ts](../scripts/select-park-paths.ts)가 공원 경계 안쪽만 남깁니다.
- 결과 GeoJSON은 `public/data/gwanggyo/`에 저장됩니다.

## 자료 출처와 라이선스

기본 경계, 건물, 보행로, 개별 수목, 수림대, 시설물은 [OpenStreetMap](https://www.openstreetmap.org/) 자료를 Overpass API로 조회합니다. OSM 데이터는 [ODbL](https://www.openstreetmap.org/copyright)의 적용을 받으므로 재배포하거나 가공 자료를 공개할 때 OSM 저작권 고지를 지켜야 합니다.

위성 수관 높이 자료는 Meta와 WRI의 [Canopy Height Maps v2](https://registry.opendata.aws/dataforgood-fb-forestsv2/)(CHMv2, 2026-03 공개)입니다. 공개 COG 자료의 라이선스 표기는 CC BY 4.0입니다. 공원 일대의 원본 영상은 2019-02-24 촬영분입니다(타일 메타데이터 `acq_date`). 재사용할 때 원 자료의 저작자 표시와 라이선스 조건을 확인하세요.

상록·낙엽 비율과 낙엽수의 계절 곡선은 [Copernicus Sentinel-2](https://registry.opendata.aws/sentinel-2-l2a-cogs/) L2A 영상에서 추정합니다. Copernicus 자료는 무료·공개이며 가공 자료를 재배포할 수 있고, "Contains modified Copernicus Sentinel data 2023–2025" 형태의 출처 표기가 필요합니다.

지도 배경은 [OpenFreeMap](https://openfreemap.org)의 Positron 스타일입니다. 타일 제공자의 최신 이용 조건과 필요한 출처 표기를 따르세요.

## 데이터 생성

```bash
npm install
npm run fetch:osm                 # OSM 조회와 정적 레이어 생성
npm run fetch:osm -- --force      # Overpass 캐시 무시
npm run fetch:canopy              # CHM 수관 레이어 생성
npm run fetch:leaf                # Sentinel-2 상록 비율을 수목 레이어에 기록
```

Overpass 응답은 `.cache/osm/`에 캐시됩니다. `fetch:osm`은 공원 경계와 AOI, 건물, 보행로, 개별 나무, OSM 수림대, 시설물 GeoJSON을 생성하고, CHM 마스킹용 AOI 전체 건물 footprint도 캐시합니다.

`fetch:canopy`는 OSM 생성이 끝난 뒤 실행합니다. Meta·WRI CHMv2 COG(z10 quadkey `1321103203`)에서 AOI 창을 읽어 `canopy_chm.geojson`을 만들고 읽은 래스터 창을 `.cache/chm/`에 캐시합니다.

`fetch:leaf`는 마지막에 실행합니다. 앞의 두 명령이 `trees`, `canopy`, `canopy_chm` 파일을 다시 쓰면 `evergreenShare` 속성이 사라지므로 그 뒤에 다시 실행해야 합니다. 장면별 NDVI는 `.cache/s2/`에 캐시됩니다.

공원 보행로만 다시 만들 때는 캐시된 AOI 보행망과 공원 경계를 사용합니다.

```bash
node --import tsx scripts/select-park-paths.ts
```

상류 자료가 바뀌면 결과도 달라질 수 있습니다. 생성 스크립트는 정적 데이터를 덮어쓰므로, 이전 결과가 필요하면 `public/data/gwanggyo/`를 별도로 보관하세요.

## 생성되는 레이어

| 파일 | 내용 |
| --- | --- |
| `park.geojson` | 공원 경계와 원천·신대 저수지 |
| `aoi.geojson` | 공원·저수지 주변 500 m 버퍼 |
| `buildings.geojson` | 공원에 그림자가 닿을 수 있는 건물 |
| `paths.geojson` | 공원 안으로 잘라낸 OSM 보행로 |
| `trees.geojson` | `natural=tree` 점 자료 |
| `canopy.geojson` | OSM 수림대·숲 폴리곤 |
| `structures.geojson` | 정자·파고라·교량 등 시설물 |
| `canopy_chm.geojson` | CHM 높이 구간에서 만든 수관 폴리곤 |

CHM 폴리곤은 개별 나무 목록이 아닙니다. 같은 위치에 여러 높이 구간이 겹칠 수 있고, 계산에서는 겹친 영역을 하나의 그늘로 처리합니다.

## 높이 정규화

[src/lib/buildings.ts](../src/lib/buildings.ts)의 `normalizeBuildingHeight()`가 건물 높이를 다음 순서로 정합니다.

1. `height` 태그를 사용합니다. 미터와 feet 표기를 읽어 미터로 변환합니다.
2. 높이가 없으면 `building:levels × 3 m`를 사용합니다.
3. 둘 다 없으면 건물 유형별 기본값을 사용합니다.

AOI 안에서 높이 또는 층수가 확인된 같은 유형 건물이 5개 이상이면 그 유형의 중앙값을 지역 기본값으로 우선 사용합니다. 그 밖에는 [src/lib/config.ts](../src/lib/config.ts)의 기본값을 사용합니다.

`heightSource`에는 `osm`, `levels`, `estimated`, `chm`을 기록합니다. OSM 나무와 수림대는 `leaf_type`, `leaf_cycle` 태그도 `leafType`, `leafCycle`로 보관합니다. OSM 나무와 시설물의 `height`, 나무의 `diameter_crown`도 같은 단위 파서로 미터로 변환합니다.

## 건물 그림자 필터

생성 단계에서 모든 AOI 건물을 매번 계산하지 않도록 다음 규칙으로 줄입니다.

- 하지, 추분, 동지 날짜를 사용합니다.
- 각 날짜의 07:00부터 19:00까지 30분 간격으로 태양 위치를 계산합니다.
- 건물 자체가 공원과 겹치거나, 샘플 시각 중 하나의 그림자가 공원과 겹치면 보존합니다.
- 나머지 건물은 결과에서 제외합니다.

이 필터는 데이터 크기를 줄이기 위한 선택 규칙입니다. 모든 날짜와 시각에 그림자가 닿지 않는다는 것을 증명하는 판정은 아닙니다.

## 태양과 그림자 형상

[src/lib/sun.ts](../src/lib/sun.ts)는 SunCalc 2.x의 북쪽 기준 시계방향 방위각을 받아 라디안으로 보관합니다. 태양 위치는 공원 중심 한 좌표에서 계산하고, 선택한 시각은 한국 표준시(UTC+9)로 해석합니다.

[src/lib/shadow.ts](../src/lib/shadow.ts)의 건물 모델은 footprint를 지면에서 수직으로 올린 기둥입니다. 그림자 길이는 다음 식으로 계산합니다.

```text
shadowLength = height / tan(sunAltitude)
```

그림자는 태양의 반대 bearing 방향으로 footprint를 이동시키며 쓸어 만든 영역입니다. 태양 고도가 0.5도 이하이면 그림자를 만들지 않고, 매우 낮은 고도에서의 길이는 600 m로 제한합니다.

볼록한 footprint는 원래 꼭짓점과 이동한 꼭짓점의 convex hull을 사용합니다. 오목한 footprint와 내부 구멍이 있는 수관은 원래 영역에, 그림자 방향을 향한 경계 변들이 쓸고 지나간 띠를 `polygon-clipping`으로 합칩니다. 쓸린 점은 영역 안에 머물거나 그림자 방향을 향한 변을 마지막으로 지나 나가므로 이 합집합은 모든 변을 쓸어 합친 결과와 같습니다. 연속한 앞쪽 변들은 그림자 방향에 수직으로 단조이므로 변마다가 아니라 연속 구간마다 단순 다각형 하나로 처리합니다.

나무는 중심점 주변의 12각형 수관으로 근사한 뒤 같은 sweep을 적용합니다. 현재 모델은 수관을 지면부터 높이까지 이어진 원기둥으로 보므로 열린 줄기 아래나 수관 하단의 빈 공간은 표현하지 않습니다.

## 수관 높이 지도 처리

CHMv2 값은 1 m 단위 정수입니다. [scripts/fetch-canopy-chm.ts](../scripts/fetch-canopy-chm.ts)는 CHM 래스터를 `2, 5, 8, 11, 14, 17, 20, 23, 26 m` 기준으로 등고선화합니다. 각 기준 높이에는 기준값보다 1.5 m 높은 대표 높이를 기록하므로 낮은 기준의 수관 안에 높은 기준의 수관이 겹칩니다.

처리 순서는 래스터 창 읽기, 등고선 생성, 약 1 m 허용치 단순화, AOI 클리핑, AOI 전체 건물 footprint와 호수 수면 마스킹입니다. 20,000 m²보다 큰 폴리곤은 150 m 격자로 나누고 4 m²보다 작은 결과는 버립니다.

CHM 자료가 있으면 넓은 OSM 수림대는 같은 영역을 중복해서 채우지 않도록 대체 자료로만 사용합니다. 개별 OSM 나무와 시설물은 유지합니다. CHM 폴리곤 수를 나무 그루 수로 해석하지 않습니다.

## 상록·낙엽 비율과 계절

[scripts/fetch-leaf-phenology.ts](../scripts/fetch-leaf-phenology.ts)는 Element 84 Earth Search STAC에서 2023–2025년 MGRS 52SCG 타일의 Sentinel-2 L2A 장면(타일 구름 40% 미만)을 찾아 AOI 창만 읽습니다.

1. 10 m 적색·근적외 밴드로 NDVI를 계산하고, 20 m SCL에서 식생(4)·비식생(5)으로 분류된 화소만 사용합니다. 구름, 그림자, 물, 눈 화소는 제외하고 AOI의 절반 이상이 맑지 않은 장면은 버립니다.
2. 화소별로 겨울(12–2월)과 여름(6–9월) NDVI 중앙값을 만듭니다. 관측이 3회 미만이면 값을 두지 않습니다.
3. CHM 8 m 이상이고 여름 NDVI 0.6 이상인 큰 수관 화소에서 겨울 NDVI 5·95 백분위를 낙엽·상록 끝값으로 보고, 각 화소의 겨울 NDVI를 그 사이 위치로 바꿔 `evergreenShare`(0 낙엽 … 1 상록)를 만듭니다. 2026-09 CHMv2 기준 실행에서 끝값은 0.235와 0.584였습니다.
4. CHM·OSM 수림대 폴리곤은 내부 화소 중심의 평균을, 개별 나무와 화소보다 작은 폴리곤은 해당 위치의 화소 값을 기록합니다. OSM `leaf_cycle`·`leaf_type` 태그가 있으면 위성 추정보다 태그를 우선합니다.

같은 스크립트는 뚜렷한 낙엽 화소의 장면별 NDVI를 겨울·여름 수준 사이 비율로 출력합니다. [src/lib/config.ts](../src/lib/config.ts)의 `DECIDUOUS_LEAF_CURVE`는 이 값에 맞춘 구간 선형 곡선입니다. 4월 초에 잎이 나기 시작해 4월 15일 무렵 절반, 5월 10일 무렵 완전히 자라고, 10월 말부터 지기 시작해 11월 중순 절반, 12월 초에는 모두 집니다.

실행 시 선택한 날짜의 낙엽수 잎 비율 `L`로 수관의 상대 그늘을 정합니다.

```text
낙엽 수관 그늘 = LEAFLESS_CROWN_SHADE + (1 − LEAFLESS_CROWN_SHADE) × L
수관 그늘      = evergreenShare + (1 − evergreenShare) × 낙엽 수관 그늘
```

`LEAFLESS_CROWN_SHADE`(0.3)는 잎이 진 가지가 만드는 그늘에 대한 **모델 가정**이며 측정값이 아닙니다. `evergreenShare`가 없는 수목은 계절 자료가 없던 때처럼 1년 내내 완전한 그늘로 계산합니다. 건물과 시설물의 그늘은 항상 1입니다.

## 수관 하단

나무와 수관은 지면이 아니라 높이의 `CROWN_BASE_RATIO`(0.3, 모델 가정)부터 시작하는 원기둥으로 봅니다. 수관 footprint를 수관 하단 높이의 그림자 길이만큼 먼저 옮긴 뒤 나머지 높이만큼 쓸어 그림자를 만들므로, 태양 쪽 수관 아래 띠는 줄기 사이로 햇빛이 드는 것으로 계산합니다. 줄기 자체의 그림자는 무시합니다.

## 공원 육지 그늘

[src/lib/parkShade.ts](../src/lib/parkShade.ts)의 `createParkGround()`는 공원 경계 합집합에서 물과 건물 footprint를 뺍니다. 결과는 통행 가능 구역이 아니라 분석 대상에서 수면과 건물을 제외한 지면입니다.

`buildParkGroundGrid()`는 지면 폴리곤 면적을 별도로 계산하고 8 m 간격 중점 격자를 만듭니다. 격자점이 지면 안에 있을 때만 보관하고 위도에 따른 경도 방향 면적 차이를 cosine 가중치로 반영합니다.

각 격자점은 덮고 있는 그림자 중 가장 강한 상대 그늘 값(0–1)만큼 그늘로 셉니다. 그 가중치의 합을 전체 격자 가중치의 합으로 나누고, 그 비율을 지면 폴리곤 면적에 곱합니다. 8 m보다 좁은 띠, 경계, 작은 빈 공간은 격자 해상도 때문에 근사됩니다.

## 산책길 그늘

[src/lib/shade.ts](../src/lib/shade.ts)의 `buildSegmentGraph()`는 보행로를 최대 10 m 길이의 연결된 구간으로 나눕니다. `flagPathsInPark()`는 20 m 간격 표본의 절반 이상이 공원 안에 있는 경로를 공원 경로로 표시합니다.

각 구간은 최대 5 m 길이의 동일한 셀로 나누고 셀 중점이 그림자 안인지 검사합니다. 구간별 비율은 중점마다 덮고 있는 가장 강한 상대 그늘 값의 평균이며, 전체 산책길 비율은 구간 길이를 가중치로 한 평균입니다. 공원 육지 면적 비율과 산책길 길이 비율은 서로 다른 지표입니다.

`createPolygonIndex()`가 반환하는 함수형 공간 인덱스는 폴리곤 bounding box를 약 50 m 셀에 넣어 후보를 줄인 뒤 실제 point-in-polygon 검사를 수행합니다.

## 실행 시 계산 흐름

태양 위치, 날짜의 잎 비율, 레이어 선택이 바뀌면 건물·수목 그림자를 만들고 그림자 합집합, 산책길 비율, 공원 육지 비율을 차례로 계산합니다. 지도에는 완전한 그늘의 합집합을 진하게, 그 밖의 부분 그늘(잎이 적은 낙엽 수관)의 합집합을 옅게 그립니다. 이 두 합집합과 차집합은 화면 표시에만 쓰이며, WebAssembly로 빌드한 Clipper([js-angusj-clipper](https://github.com/xaviergonz/js-angusj-clipper), MIT)를 불러올 수 있으면 그것으로, 아니면 `polygon-clipping`으로 계산합니다. Clipper는 좌표를 공원 중심 기준 약 1 cm 정수 격자로 바꿔 계산하므로 경계가 1 cm 안팎에서만 다릅니다. 그늘 비율은 두 경우 모두 개별 그림자를 직접 표본 조사하므로 같습니다. [src/lib/shadow-engine.ts](../src/lib/shadow-engine.ts)가 초기 격자와 경로 구조를 한 번 준비하고, [src/workers/shadow.worker.ts](../src/workers/shadow.worker.ts)가 반복 계산을 Web Worker에서 실행합니다. Worker를 사용할 수 없으면 같은 계산 함수를 메인 스레드에서 사용합니다.

## 정확도와 해석의 한계

- OSM 태그가 없는 건물은 추정 높이를 사용하므로 실제 높이와 다를 수 있습니다.
- 상록 비율은 10 m Sentinel-2 화소에서 추정하므로 작은 나무, 가로수, 숲 가장자리는 주변 잔디·포장면과 섞입니다. 겨울 NDVI는 하층 식생, 비탈 방향, 지면 상태의 영향도 받습니다. 끝값은 AOI 안의 분포에서 정한 상대값이라 순수한 상록·낙엽 표본으로 검증하지 않았습니다.
- 낙엽 곡선은 공원 전체 낙엽 수관의 평균이며 수종별 개엽·낙엽 시기 차이와 해마다의 기상 차이는 반영하지 않습니다.
- CHM은 과거 위성 영상과 모델에서 나온 추정치라 최근 식재·벌목, 위치와 높이 변화가 반영되지 않을 수 있습니다.
- 건물은 평평한 지면 위의 수직 기둥으로 계산하므로 지붕, 옥탑, 필로티, 층별 셋백을 표현하지 않습니다.
- 나무와 수관은 단순한 원기둥·높이층 모델이라 실제 수관 형태와 줄기 아래의 햇빛을 표현하지 않습니다.
- 건물·수면 마스크가 물이나 지붕 위에 뻗은 실제 수관 일부까지 제거할 수 있습니다.
- 지형의 높낮이는 사용하지 않고 태양 위치는 공원 중심 한 점에서 계산합니다.
- 좌표 이동은 짧은 거리용 등거리 근사이며 600 m 상한과 0.5도 고도 하한이 있습니다.
- 공원 면적은 8 m 격자, 산책길은 5 m 중점 표본을 사용하므로 그보다 작은 그림자와 경계는 정확히 측정하지 않습니다.
- 결과는 현장 측량이나 보행 안전·접근성 판정이 아닙니다. 공원 육지 지표에는 숲과 관리 제한 구역이 포함될 수 있습니다.

## 수목 자료 정확도 검증

2026-09에 공원 산책길 표본(5 m 간격, 5,955점)과 NASA GEDI 위성 LiDAR로 수목 자료를 점검했습니다.

- **계산 방식의 오차는 작습니다.** CHM을 3 m 높이 구간 폴리곤으로 바꾼 현재 방식과 원본 래스터를 광선 추적한 결과는 표본의 97–99%에서 같았고, 산책길 그늘 비율 차이는 1%p 안팎이었습니다.
- **입력 자료가 결과를 좌우합니다.** 같은 광선 추적에서 높이 ±15%는 그늘 비율을 0.4–1.6%p, 수관 경계 ±1 화소(약 1.2 m)는 약 ±3%p 바꿨습니다. 수관 하단 비율(0–0.5)은 2%p 미만이었습니다.
- **CHM v1에서 v2로 바꾼 근거.** 기존 v1(2024)은 같은 2019-02-24 영상을 쓰지만 공원 수관을 크게 낮게 추정했습니다. [scripts/validate_canopy_gedi.py](../scripts/validate_canopy_gedi.py)로 품질·경사·건물 거리 조건을 통과한 GEDI 관측(2019–2025)과 비교한 결과는 다음과 같습니다.

| 비교 (CHM p98 − GEDI rh98) | v1 | v2 |
| --- | --- | --- |
| 전체, 반경 12.5 m, 중앙 편향 | −7.3 m | −3.4 m |
| 전체, 반경 22.5 m, 중앙 편향 | −6.1 m | −2.5 m |
| 수관 피복 30% 이상, 반경 22.5 m, 중앙 편향 | – | −0.1 m |

GEDI 관측 지름(약 25 m)과 위치 오차(약 10 m) 때문에 성긴 수관에서는 이웃 나무가 섞여 음의 편향이 커 보입니다. v2 편향은 관측 연도(2020 −2.5 m, 2024 −2.7 m, 2025 −2.0 m)에 따라 뚜렷한 추세가 없어 2019년 이후 성장 보정은 적용하지 않았습니다. v2로 바꾸면 여름 산책길 그늘 비율이 시각에 따라 약 8–16%p 높아집니다.

남은 한계는 겨울 낙엽기 영상이라는 점, 작은 수관의 경계, 2019년 이후 변화입니다. 개별 어린 나무는 현장 기반 OSM 기여나 공개 수목 대장이 있어야 정확해집니다.

## 검토 후 사용하지 않은 자료

- **산림청 임상도**: 1:5,000 파일은 공공누리 제3유형(변경금지)이고, 산림청 개방 안내는 공공기관의 비영리 공공사업이나 학술·연구 목적 제공으로 한정합니다. 1:25,000은 공공데이터포털 표기(제한 없음)와 산림청 안내가 달라 사용 조건이 명확하지 않습니다. 가공 결과를 공개 저장소에 두는 이 프로젝트에는 사용하지 않습니다.
- **국토지리정보원 수치표면모델·항공 LiDAR**: 공개제한 공간정보로 신청과 보안 심사를 거쳐 제공되는 자료라 재배포 조건이 맞지 않습니다. 검증 용도로도 사용하지 않습니다.
- **V-World 3D 공간정보**: 약관이 사전 승낙 없는 복제·변경·제공을 금지하고 3차원 공간정보를 공개제한 정보로 다룹니다.
- **국토지리정보원 정사영상**: 데이터 표기는 이용 제한이 없지만 측량성과를 활용한 지도 배포 심사(공간정보관리법 제15조) 적용 여부가 불확실해 확인 전에는 사용하지 않습니다.
- **ESA WorldCover, 10–30 m 수관 높이 지도, Mapillary**: 공원 규모의 개별 수관을 구분하기에 해상도가 낮거나(WorldCover는 잔디와 나무가 섞인 공원 대부분을 나무로 분류), 나무 객체가 없습니다.
- **전국가로수길정보표준데이터**: 이용 제한은 없지만 가로수길 시작·끝 좌표와 수량만 있는 구간 자료이고, 대부분 공원 밖 도로입니다. 개별 나무 위치가 필요한 이 계산에는 보류했습니다.

개별 수목 자료를 늘리는 방법은 [OSM 수목 기여 안내](osm-tree-mapping.md)를 참고하세요.

생성 데이터와 계산 규칙을 바꾼 뒤에는 `npm test`, `npm run typecheck`, 필요하면 `npm run bench`로 결과와 성능을 확인하세요.
